# 来源、精度与资源核验

## 每个条目必填

地点条目填写稳定 ID、名称、主分类、世界属性、地点/作品、标签和来源链接；有三维资源时再提供覆盖范围、重建方法、精度依据、作者与许可资料。无依据的展示字段省略。真实场景尽量记录采集时间；历史场景必须说明复原时期；虚构场景必须区分原作依据与创作补全。

## 两条独立的质量轴

**视觉表现**记录表现方式、可见细节、材质、交互和浏览限制。可以写“体素风格，有四季与昼夜交互”，不能从这些特征推出厘米级精度。

**几何与考据**记录来源方式、坐标参考、单位、标定、覆盖范围、已知误差和推定内容。仅当有报告、测量数据或作者可核验声明时填写定量误差，并注明声明主体。照片和地图推定不能写成测绘；文学复原明确标注其艺术重构属性。

## 来源类型

| 来源方式 | 应记录的证据 |
| --- | --- |
| 实测 / 激光扫描 | 采集方式、时间、坐标系、配准与精度报告（如有） |
| 摄影测量 | 图片或航拍来源、重建方法、尺度标定与覆盖缺口 |
| 地图 / 卫星 / 建筑轮廓 | 数据源、版本、实际高度与估计高度的区别 |
| 手工建模 | 参考照片、图纸、作者说明和不可见部分的推定 |
| 历史文献重构 | 年代、文献/考古依据、不同版本及推定部分 |
| 文学或原创空间 | 作品出处、设定范围、艺术补全与虚构尺度 |

来源的 `role=place` 只证明地点或作品；`role=asset` 才是模型/场景来源。官网或 UNESCO 条目不作为“三维模型已存在”的证据。代码许可证不自动覆盖数据、纹理、照片和模型。

## 合并前检查

1. 打开来源与预览，确认内容和名称相符，记录日期。
2. 验证下载指向实际文件或明确的数据下载页；标明格式、大小、版本与 SHA-256（本地文件应提供）。
3. 检查覆盖范围、来源、精度局限和授权声明。缺失字段留空，不在展示页面输出推测或占位说明。
4. 检查网页加载错误、主要交互、桌面与手机可读性；性能或 WebGL 限制应说明。
5. 更新状态。资源失效转为 `unavailable`；未经验证的上游线索保持 `external`。

浏览验证与视觉验收分开记录。项目不提供统一“五星精度”评分。新贡献不得自动变成已验证条目；由维护者根据实际检查合并。
